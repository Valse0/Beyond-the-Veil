## How to use this ledger

- The atomic inventory is the source of truth for individual requirements. The six-stage dashboard summarizes `PLAN.md`; it does not replace requirement-level tracking.
- A requirement is counted once, regardless of how many implementation packages or tests touch it.
- **VERIFIED** means the stated acceptance criteria have current, relevant evidence. A green CI run alone does not verify untested behavior or physical-device requirements.
- **IMPLEMENTED_UNVERIFIED** means the implementation exists, but one or more acceptance checks still lack sufficient evidence.
- **IN_PROGRESS** means only part of the requirement is implemented, or meaningful integration/content/UX work remains.
- **NOT_STARTED** means implementation has not begun. Use **BLOCKED** only with a named blocker; use **DEFERRED_WITH_APPROVAL** only with recorded approval.
- Final art/audio, natural-run balance, mobile/controller/TV and physical-device checks remain open unless a row explicitly records evidence for them. Do not promote a requirement based only on placeholder rendering or catalog data.
- Historical CI/session entries are retained for traceability. They are not current status declarations.
